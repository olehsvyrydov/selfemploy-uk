# Release Checklist

No release has been cut from this repository yet (there is no `v*` tag). This is the checklist to
run through before pushing the first tag, and every tag after it. Nothing here cuts the tag —
that is a separate, deliberate step at the end.

## Before tagging

- [ ] `mvn -o clean install` is green (default reactor).
- [ ] `mvn -o -Pserver clean install` is green (`-Pserver` profile).
- [ ] `scripts/content-lint.sh` is clean.
- [ ] Next tax year's rate file is present under `core/src/main/resources/tax-rates/` (as of this
      checklist, `2024-25.yaml`, `2025-26.yaml`, and `2026-27.yaml` all exist — reconfirm the
      current and next tax year are both there before tagging).
- [ ] `CHANGELOG.md` has an entry for the release under a dated version heading, not `[Unreleased]`.
- [ ] `RELEASE_NOTES.md` (this repo's template, see below) is filled in for the release, including
      the HMRC integration section — which must come from a **recorded sandbox walkthrough run
      against this exact commit**, not from reading the code.
- [ ] README has no dead links (`scripts/content-lint.sh` catches blocked phrases; links still need
      a manual check — there is no automated link checker in this repo yet).
- [ ] The version being tagged matches the Maven project version (`pom.xml`) that will actually be
      built by the release workflow.

## Tagging

- [ ] Tag is `vX.Y.Z` (the release workflow only triggers on `v*` and only accepts a numeric
      `x.y.z` prefix — see `.github/workflows/release.yml`).
- [ ] Tag is pushed to `main` after the above are all checked, not to a feature branch.

## After the release workflow runs

- [ ] All five installer artifacts built (Windows `.msi`, macOS `.dmg`, Linux `.deb`/`.rpm`/
      `.AppImage`).
- [ ] `SHA256SUMS` is present among the release assets (generated by the `Generate SHA-256
      checksums` step in `.github/workflows/release.yml`).
- [ ] Spot-check: download one installer and its `SHA256SUMS`, and verify manually
      (`sha256sum -c SHA256SUMS --ignore-missing`) before announcing the release.
- [ ] `./install.sh --install` succeeds end to end against the published release on at least one
      platform.
